# SCRUBBOTS Visual Reference Library

Canonical guide for all visual assets entering the SCRUBBOTS project.

## Visual authority hierarchy

1. **Owner-approved original SCRUBBOTS artwork** — canonical visual
   reference. Characters, gameplay concepts, five-slot layouts, pixel-art
   level artwork, themed level art, UI ideas, effects. If original approved
   artwork conflicts with a generic placeholder, the original wins.
2. **Owner-supplied SCRUBBOTS reference images** — secondary project
   reference. May guide composition, proportions, pixel density, UI
   positioning, Scrubbot size, slot size, board presentation, visual
   hierarchy.
3. **External game references** — inspiration only. Movement density,
   clarity, pacing, spatial readability, touch ergonomics, pixel
   construction methodology. Must never be copied.

## Source classes

| Class | Meaning | Production use |
| --- | --- | --- |
| `OWNER_ORIGINAL` | Created by or for the SCRUBBOTS project, approved by owner | Canonical production art |
| `OWNER_REFERENCE` | Supplied by owner as visual guide, not production art | Composition/style reference only |
| `EXTERNAL_INSPIRATION` | Third-party game/art used as conceptual reference | Never copied into SCRUBBOTS assets |
| `PROJECT_BRANDING` | Company/attribution branding (e.g. Akilta wordmark) | Outside gameplay/reference art |

## Approval and availability states

| State | Meaning |
| --- | --- |
| `APPROVED` | Owner has explicitly approved for its intended use |
| `SUPPLIED_NOT_APPROVED` | Owner provided the file but has not approved production use |
| `AWAITING_OWNER_ASSET` | Expected category exists but no file has been supplied |
| `UNVERIFIED` | File exists but provenance/owner approval cannot be confirmed |

An asset does not become `APPROVED` merely because it exists in the
repository. Owner action is required.

## Canonical asset naming

- Stable logical IDs use lowercase, underscores, no spaces:
  `scrubbot_character_01`, `level_underwater_01`, `ref_colony_flow_movement`.
- Owner originals keep their original filename when ingested. The manifest
  ID normalizes identity while the source retains its name.
- Cross-platform safe: lowercase ASCII, underscores, hyphens. No spaces,
  no special characters beyond `-` and `_`.

## Source-original preservation

**Owner originals are immutable source artifacts.** Once an owner-supplied
file is ingested into `assets/art/`, it must be preserved byte-for-byte
in its original location.

Future derived outputs — resized versions, palette extractions, previews,
gameplay-converted level data, cropped thumbnails — must be separate files
in appropriate output directories (e.g. `assets/art/levels/previews/`),
never in-place overwrites of the source.

## Intake process for new owner assets

1. Owner supplies file(s) with clear identification.
2. Verify provenance — do not assume filenames prove origin.
3. Copy to the appropriate source directory preserving the original
   filename.
4. Add an entry to `assets/art/references/inventory.json` with:
   - stable logical ID
   - source class and category
   - availability: the file's path
   - approval status (default `SUPPLIED_NOT_APPROVED` until owner confirms)
   - original filename
   - notes/provenance
5. If dimensions/difficulty are reliably known, record them. Do not guess.
6. Update `tasks.md` to reflect truthful availability — never mark an
   inventory task complete without the actual verified file.

## Allowed use of external inspiration

External references (e.g. Colony Flow) may be recorded as textual
provenance/context entries in the inventory. They describe the conceptual
inspiration and explicitly state that no copied asset is adopted as
project art.

Colony Flow is referenced only for the broad feeling of many tiny agents
moving across a play area. SCRUBBOTS intentionally differs:

```
slot -> Scrubbot leaves -> travels to valid pixel -> cleans pixel -> disappears
```

Never reproduce Colony Flow characters, art, levels, UI, icons,
compositions, exact animations, routing visuals, or source code.

Do not download new external reference images during implementation
cycles. A textual record suffices.

## Prohibition on fabricated originals

Missing owner artwork must never be:
- generated by AI or any tool and labeled as original
- guessed from textual descriptions
- copied from external sources and relabeled
- represented as physically present when absent

Use `AWAITING_OWNER_ASSET` for every expected-but-absent category.

## Progression from reference to production candidate

```
Owner supplies file
  -> ingested into assets/art/ (source-original preserved)
  -> M08: full technical pixel/dimension audit
  -> M09: pixel-art importer converts to Level Data
  -> M10: DIRTY/CLEAN visual treatment applied (owner design gate)
  -> production candidate validated against difficulty bands
```

## M08 boundary

M07 establishes the library structure, naming, intake rules, and
availability audit. M08 performs the full per-file technical audit:
filename, original dimensions, alpha/transparency, color count,
anti-aliasing detection, interpolation detection, logical-pixel grid,
legal difficulty band, source preservation verification. Do not perform
M08 work in M07.

## M10 DIRTY/CLEAN design gate

The visual reference library preserves these rules:
- CLEAN is the unmodified source palette color.
- DIRTY must remain recognizably related to the underlying hue while
  being clearly distinct using both saturation and brightness/value
  differences (never saturation alone).
- Three prototype presets (A/B/C) exist in `DirtyCleanPresets`.
- Final DIRTY treatment requires owner review at realistic 50×50 and
  59×59 display scale via `scenes/debug/board_renderer_debug.tscn`.
- M07 must not mark M10 complete or choose a final preset.

## Directory structure

```
assets/art/
├── references/
│   ├── README.md              <- this file
│   ├── inventory.json         <- machine-readable inventory
│   ├── gameplay/              <- owner gameplay-screen references
│   ├── ui/                    <- owner UI references
│   ├── scrubbots/             <- owner Scrubbot character references
│   ├── pixel_method/          <- pixel-construction method references
│   └── external_inspiration/  <- external game references (text only)
├── characters/
│   └── scrubbots/             <- owner-approved Scrubbot character art
├── levels/
│   ├── source/
│   │   ├── easy/              <- owner level art (20-29 dimensions)
│   │   ├── medium/            <- owner level art (30-39 dimensions)
│   │   ├── hard/              <- owner level art (40-49 dimensions)
│   │   └── very_hard/         <- owner level art (50-59 dimensions)
│   └── previews/              <- derived preview thumbnails (never source)
├── ui/                        <- owner UI art
└── effects/                   <- owner effects art
```
