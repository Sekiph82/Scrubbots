# Difficulty lane anchor calibration (SB-M36-013)

Status: decision rule and anchor corpus declared BEFORE any Challenge measurement (this
section 1-3 text is committed in the same commit as the fixtures, before `anchors_v2.json`).

## 1. Purpose

Decide whether the v1 lane targets (`data/config/level_progression_v1.json`: EASY 20, MEDIUM 40,
HARD 58, VERY_HARD 76) fit the v2 Challenge Score scale, using a purpose-built ANCHOR CORPUS of
deterministic TEST fixtures designed from the score-component rules. Shipped campaign levels and
owner ratings are not calibration targets, anchors or acceptance criteria. The analyzer, its
configs and coefficients are unchanged; only the lane file may change, by the rule below.

## 2. Decision rule (fixed before measurement)

Let `M_L` be the median D of the 5+ non-EXTREME anchors of lane L (EXTREME probes are reported as the ceiling and never enter `M_L`). Let `T_L` = v1 lane base (EASY 20, MEDIUM 40, HARD 58, VERY_HARD 76), tolerance `tol` = 5.0 (v1 `challengeTolerance.neverForceLabelOutsidePlusMinus`).

- Step 1 (monotonic test, always): `M_EASY < M_MEDIUM < M_HARD < M_VERY_HARD`. If it FAILS: write NO level_progression_v2.json, no rescale; record a "MODEL FINDING: lane ordering not monotonic on anchors" in the doc and TASKS.md (new follow-up task line), and stop the decision there.
- Step 2 (only if step 1 passes): lane L "holds" if `|M_L - T_L| <= tol` AND at least 4 of its anchors lie within `T_L +/- 2*tol`. If ALL four lanes hold: KEEP lanes, add no progression v2 file, report "no rescale".
- Step 3 (otherwise): create `data/config/level_progression_v2.json` (schema `scrubbots-level-progression/v2`, version 2, same shape as v1; cadence, modifiers, roles, noveltyTarget, progression form `1-exp(-k/20)`, tolerances, envelope sections copied from v1). `lanes.L.base = round(M_L, 1)`. Scale `s = (M_VERY_HARD - M_EASY) / (76 - 20)`; `lanes.L.growth = round(v1 growth_L * s, 1)`; `recoveryGuards.minimumChallengeDrop = round(v1 drop * s, 1)`. Add a `calibration` block listing the anchors manifest sha256, measured medians, `s`, rule version and analysis/score config sha256. `challengeTolerance` stays as v1 unless `s` < 1, in which case multiply the three values by `s` (rounded 0.1). Cap check: `base+growth` of VERY_HARD must be <= the best EXTREME-probe D; if not, flag it as a ceiling finding in the doc (still emit the file; do not invent new mechanics).

Rule version: `sb-m36-013-anchor-lane-rule/v1` (implemented by `tools/measure_difficulty_anchors.gd`
`decide()` and recomputed independently by `tests/m36_anchor_calibration.gd`).

## 3. Anchor corpus (declared before measurement)

Generated by `tools/build_difficulty_anchors.gd` into `tests/fixtures/difficulty_anchors/`
(QA-only, `"difficulty": "TEST"`, level data version 1, canonical C01..C14, <= 12 colours, 24..28
cells per side, every fixture legal and SOLVED by the canonical solver at build time). Design
intent per lane from the component rules (docs/09, docs/10, `level_difficulty_analysis_v2.json`
operational definitions):

- EASY: open access, 3-5 colours, shallow unlock, many simultaneous targets.
- MEDIUM: moderate enclosure, 5-8 colours.
- HARD: deep unlock chains with a few bottlenecks, 8-10 colours.
- VERY_HARD: deep enclosure, narrow bottlenecks, 10-12 colours, long routes, slot pressure.
- EXTREME (ceiling probes, never in a lane median): legal designs maximising A, U, B, R, S together.

Building blocks: shapes `vstripes`, `hbands`, `tiles`, `frame`, `shafts`, `rings(rw, ns)` and
`maze` (single-entrance serpentine corridor); supply strategies `layer_rr`, `color_first`,
`layer_split` and `straddle30` reused from `tools/calibrate_difficulty_v2.gd` `build_supply`.
The per-fixture rationale and intended component profile are in
`tests/fixtures/difficulty_anchors/anchor_manifest_v1.json`.

Pre-measurement replacement (solvability only): the first draft probe `x_rings12q_r1_straddle_24`
(1-wide quadrant rings, straddle30 supply) was DEADLOCK under the canonical solver and was replaced
by `x_rings12q_straddle_24` (2-wide quadrant rings, straddle30) before any measurement.
