# SB-M37-007 — Service implementation

Status: IMPLEMENTED
Requirement: narrow progression service separated from UI, economy, and save
serialization. M40 owns durable save. Snapshot/import seams only if needed,
without a competing save format.

## Production owner
`scripts/progression/level_progression_service.gd`:
- holds only progression state (frontier + first-clear set);
- reads M36 difficulty for class/target;
- exposes `snapshot()` -> `{schema, current_level, completed[]}` and
  `import_snapshot()` (all-or-nothing, fail-closed);
- writes NO file itself — M40 SaveService will own durable persistence.

## Direct tests
`_snapshot_roundtrip` and `_malformed_snapshot` prove versioned round-trip and
fail-closed import.

## Failure condition
Service writes its own save file, mutates economy, or partially applies a bad
snapshot.
