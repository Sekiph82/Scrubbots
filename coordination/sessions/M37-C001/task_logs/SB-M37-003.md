# SB-M37-003 — Completion tracking

Status: IMPLEMENTED
Requirement: first-clear completion idempotent by stable level number; duplicate
WON callbacks cannot advance progression twice; completion truth separate from
replay.

## Production owner
`LevelProgressionService.record_win(level_number, is_replay=false)`:
- returns true only on a NEW first-clear;
- `_completed` dict keyed by level number is the idempotent set;
- duplicate/reentrant calls return false and do not advance the frontier.

## Direct tests
`_first_clear_idempotent` — first win counts; duplicate + 10 reentrant calls do
not re-count or double-advance; completed_count stays 1.

## Failure condition
Duplicate WON advances the frontier or grows the completed set twice.

## Actual
PASS.

## Notes
First-clear truth feeds M38 win-streak / M39 first-clear rewards; those must
also key off this idempotent set (dependency documented for M38/M39).
