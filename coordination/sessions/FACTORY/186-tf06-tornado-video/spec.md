# Tornado booster video (SB-TF-06)

> Feature: Tornado booster video. Owner source Blue_tornado_spinning_and_growing_6bafdac1.mp4 (black background): trim the idle first ~0.5 s, play it additively from the Tornado booster button to the board centre, mapped to the real on-screen positions of the button and the board (any viewport); the purged colour's real board cells spiral into the growing tornado by code (correct colour per cell); after the video a quick spin-collapse + small burst by code; old vector arms/rings removed; Reduced Effects -> no video. Keep the video small, measure mobile performance, no input or gameplay change, purge result identical to today.

## Requirements
1. **Asset.** Add `assets/ui/final/boosters/videos/tornado_additive.ogv` (+ Godot's generated `.uid`) built from the source mp4: trim the idle start (builder measures the first frame where the tornado visibly moves/grows, expected ~0.5 s) and end the clip at the first frame where the tornado has reached its final centre/size (end-of-travel; the in-place spinning tail is dropped). Resulting length 1.3-2.2 s. Crop to the bounding box of all non-black pixels over the kept frames + 16 px, sides rounded up to a multiple of 16 (same method as `tools/build_result_scrubby_videos.py`). No audio (`-an`), Theora (`libtheora`), 24 fps, `yuv420p`, `-map_metadata -1`. Black must decode to ~0: if the decoded corner/background pixels exceed 4/255 per channel, crush near-black before encoding (e.g. ffmpeg `lutrgb`/`colorlevels`) so additive blending adds no grey haze. **Size budget: <= 1.5 MB target, hard fail > 2 MB** (state the final `-q:v`; start at 5 as for the other videos and lower only to meet the budget).
2. **Provenance.** `assets/ui/final/boosters/videos/PROVENANCE.md`: source file name, sha256 of the source mp4, trim start/end frames, crop (x,y,w,h), exact ffmpeg command, output sha256 and byte size, and the measured tornado **track** (below). Add a matching `ASSET_GENERATION_MANIFEST.json` entry (id e.g. `tornado_booster_video_v1`, owner decision, tool, sha256 of the .ogv, "master stays in owner Downloads, not committed"). The source mp4 stays in the job folder / Downloads, never under `res://`; do not commit it to `assets/`.
3. **Track.** The builder measures, per kept frame (bbox/centroid of pixels brighter than a threshold), the tornado centre (cx, cy) and diameter in cropped-video pixels and bakes ~12 evenly spaced keys plus first and last into a `const TORNADO_TRACK` in `booster_vfx.gd` (also listed in PROVENANCE.md); in-between values are linearly interpolated. Key 0 is the tornado at its button start, the last key is its end-of-travel position at the board centre.
4. **Layer mapping (any viewport).** `BoosterVfx` plays the clip in ONE `VideoStreamPlayer` (child of the existing overlay, created on tornado play, freed in `stop()`; never kept alive idle) with an additive `CanvasItemMaterial` (`BLEND_MODE_ADD`, no shader, no alpha key). Its position/size/scale are computed from the track so that track key 0 lands on the centre of the Tornado button's global rect and the last key lands on the centre of `get_board_rect()` (both captured when the effect starts, from the real nodes, not constants). Axis-wise scale `(sx, sy)` + translation, no rotation; each of sx, sy = screen distance / track distance on that axis, and `max(sx,sy)/min(sx,sy) <= 1.25` at every viewport in the sb_tf04 matrix (see AC). The player ignores mouse input (`MOUSE_FILTER_IGNORE`) and stays under the overlay's input-transparent rule.
5. **Cells by code.** While the video plays, the purged colour's real board cells are pulled into the growing tornado: the existing one-`ImageTexture` ghost (every purged cell, canonical colour, from `capture_booster_fx`) is translated toward the tornado's current track position (pivot = cells' centroid), rotating and shrinking with ease-in over the video duration, fading as it reaches the eye; the <= 48 board `samples` and the supply/slot `tiles` spiral to the CURRENT tornado position (not a fixed point), staggered by their `delay`. Colours come only from the captured data (a red purge shows red cells). No Node per cell; `capture_booster_fx` data keys the old tests rely on (`ghost`, `board_rect`, `center`, `cell`, `samples`, `tiles`) keep their meaning; add `button_center` and `board_center` (global) to the captured dict.
6. **Collapse.** After the video's last frame (the player is paused on it, not looped), code runs a spin-collapse of that layer around the board-centre tornado position (rotates ~1.5 turns while scaling to ~15 %, 0.25 s, ease-in), then the existing `BURST_ART` burst (0.25 s). Total effect = clip length + ~0.5 s. `DURATION["tornado"]` becomes this computed total (set at `play()`); other boosters' durations unchanged.
7. **Removal.** The 3 spiral arms and 2 dashed rings in `_draw_tornado()` are deleted (no vector vortex remains). Keep the tile/sample spiral and the burst drawing.
8. **Gameplay untouched.** The purge, economy, charges, input and the 48-sample/ghost data come from the same call order as today (capture BEFORE, effect AFTER commit). The board is never redrawn or hidden by the video; `BoardRenderer` is not edited; no input is blocked while the effect plays; the result of `execute_booster("tornado", colour)` (r dict, resulting board/supply/slot snapshots, charge/SB deltas) is identical to `main`.
9. **Reduced Effects.** When Reduced Effects is on: no `VideoStreamPlayer` is created, no ghost, no `BoosterVfx` play (today's behaviour: only the button's `ActivatedBurst` flash). Turning it on mid-effect calls `stop()` which frees the player.
10. **Failure path.** If the stream is missing, fails to open, or reports length <= 0, the effect still runs code-only (cells spiral toward `board_center`, collapse + burst) over a fixed fallback duration equal to the clip length; no error is raised, no node leaks.

## Assumptions
- "Idle ~0.5 s" is measured from frames rather than fixed at 0.5 s; the end is cut at end-of-travel because the owner brief only needs the growth (~2 s source) and a code collapse follows; keeps the file small.
- Axis-wise scale (no rotation) is used so both endpoints match exactly on any aspect ratio; the tornado is rotationally symmetric so the slight stretch is acceptable, bounded by the 1.25 ratio check.
- Reduced Effects keeps today's behaviour (button flash only); the "existing simple purge feedback" is that flash, nothing new is added.
- Video resolution is the cropped native size (no downscale) since the clip is a soft glow; downscale only if the 2 MB hard limit cannot otherwise be met.
- Cells spiral by the existing ghost + <= 48 samples (cheapest way to keep the correct colour for every cell with one texture); a per-cell particle system is not built.
- Theora (not H.264/WebM) because Godot 4.7.2 only plays `.ogv`, as with every other game video.
