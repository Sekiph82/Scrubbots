## Requirements
1. **Anchor corpus**: new fixtures in `tests/fixtures/difficulty_anchors/` (level + supply JSON each, plus `anchor_manifest_v1.json`), generated by a new deterministic tool `tools/build_difficulty_anchors.gd` (fixed seeds, no randomness from time; rerun yields identical bytes). TEST only: never in the production catalog/campaign manifests, never under `res://data/levels`, outside the 20..59 production envelope rules is allowed but prefer 20..40. Colours <= 12 canonical (C01..C16 only). Level data version per existing fixtures (void-free = 1).
2. At least 5 fixtures per lane (EASY, MEDIUM, HARD, VERY_HARD) = 20 lane anchors, each lane intentionally spanning the lane's design range (not 5 near-copies), PLUS at least 4 `EXTREME` ceiling probes (legal designs maximising A, U, B, R, S together: deep enclosure/unlock chains, forced single-choice bottlenecks, 12 colours, adversarial slot/colour pressure). Design intent per lane, from the rule definitions: EASY = open access, 3-5 colours, shallow unlock, many simultaneous targets; MEDIUM = moderate enclosure, 5-8 colours; HARD = deep unlock chains with a few bottlenecks, 8-10 colours; VERY_HARD = deep enclosure, narrow bottlenecks, 10-12 colours, long routes, slot pressure.
3. Every fixture declares in the manifest: id, lane (or `EXTREME`), design rationale (1-3 sentences, built from component rules; MUST NOT mention L1..L10, "first 10", owner ratings or any shipped level), the intended component profile, level/supply paths and `Pack.content_sha256` of both. Every fixture must be legal (LevelLoader validation OK) and solved by the canonical solver (`status SOLVED`); an unsolvable or inconclusive fixture is replaced, not recorded.
4. **Measurement** by a tool `tools/measure_difficulty_anchors.gd` (batched per fixture like `calibrate_difficulty_v2.gd --measure=<id>`, then a merge stage) using `LevelDifficultyAnalyzerV2` unchanged. Output `coordination/sessions/FACTORY/050-m36-013-anchor-calibration/anchors_v2.json`: per fixture D, W C A U B R S, Session Load, solver status, policy-spread, bound to the analysis/score config sha256 and fixture sha256.
5. **Decision rule (fixed here, before any measurement; do not change after seeing data)**. Let `M_L` be the median D of the 5+ non-EXTREME anchors of lane L (EXTREME probes are reported as the ceiling and never enter `M_L`). Let `T_L` = v1 lane base (EASY 20, MEDIUM 40, HARD 58, VERY_HARD 76), tolerance `tol` = 5.0 (v1 `challengeTolerance.neverForceLabelOutsidePlusMinus`).
   - Step 1 (monotonic test, always): `M_EASY < M_MEDIUM < M_HARD < M_VERY_HARD`. If it FAILS: write NO level_progression_v2.json, no rescale; record a "MODEL FINDING: lane ordering not monotonic on anchors" in the doc and TASKS.md (new follow-up task line), and stop the decision there.
   - Step 2 (only if step 1 passes): lane L "holds" if `|M_L - T_L| <= tol` AND at least 4 of its anchors lie within `T_L +/- 2*tol`. If ALL four lanes hold: KEEP lanes, add no progression v2 file, report "no rescale".
   - Step 3 (otherwise): create `data/config/level_progression_v2.json` (schema `scrubbots-level-progression/v2`, version 2, same shape as v1; cadence, modifiers, roles, noveltyTarget, progression form `1-exp(-k/20)`, tolerances, envelope sections copied from v1). `lanes.L.base = round(M_L, 1)`. Scale `s = (M_VERY_HARD - M_EASY) / (76 - 20)`; `lanes.L.growth = round(v1 growth_L * s, 1)`; `recoveryGuards.minimumChallengeDrop = round(v1 drop * s, 1)`. Add a `calibration` block listing the anchors manifest sha256, measured medians, `s`, rule version and analysis/score config sha256. `challengeTolerance` stays as v1 unless `s` < 1, in which case multiply the three values by `s` (rounded 0.1). Cap check: `base+growth` of VERY_HARD must be <= the best EXTREME-probe D; if not, flag it as a ceiling finding in the doc (still emit the file; do not invent new mechanics).

## Assumptions
- Tolerance 5.0 and "4 of 5 within 2*tol" are my conservative reading of v1 `challengeTolerance`; fixed up front so the outcome cannot be tuned afterwards.
- Medians over lane anchors (not means) so one odd fixture cannot move a lane; EXTREME probes excluded from medians because they exist to find the ceiling, not a lane.
- Growth and guards scale by one factor `s` from the EASY-to-VERY_HARD median span, keeping the v1 shape (only the scale moves), which is the smallest change consistent with "derive from anchor medians and keep the P(k) form".
- Monotonic failure is reported as a model finding with no rescale, per the request.
- Per-fixture measurement is slow (the old fresh run took ~150 s per 24x24 level); fixtures should stay 20..28 wide to keep the batch tractable, and the builder runs the measure stage in per-fixture invocations.
