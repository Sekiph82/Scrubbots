# Real-play file CLI (SB-STUDIO-REAL-PLAY-GATE, game side)

> Feature: Specify a file-based mode for the real-play check so the external Level Factory Studio can gate its release pool with the SAME check (`real_play_v1`) BEFORE a level reaches the game: inputs are a level JSON path and a supply-plan JSON path (absolute, outside res://) plus an optional JSON output path; builds a ProductionGameplayHost without registering the level in the catalog; verifies at all SENSITIVITY_DTS; `--search` runs the bounded search when the plan fails and returns robust clicks; never writes inside the repo; machine-readable JSON result (schema id, model `real_play_v1`, verdicts WON_ROBUST / WON_CANONICAL_ONLY / LOST / INVALID_INPUT / SEARCH_EXHAUSTED / SEARCH_BUDGET, per-dt results, stuck click index + slot state, searched clicks, plan sha256, game repo commit); exit codes 0/1/2; exact documented CLI usage; one small test suite; plus a Codex handoff prompt file for the Studio side.

## Context
- `scripts/gameplay/solver/real_play_driver.gd` (`RealPlayDriver`, model `real_play_v1`, consts `SENSITIVITY_DTS`, `CANONICAL_DT`, `NODE_BUDGET`, `plan_sha256()`, `dt_label()`) is the only shippability proof. `play_on_host(host, clicks, dt, ...)` is already host-agnostic. `play_level(parent, entry_id, clicks, dt, ...)` is catalog-bound: it makes a temp-save `AppState` frontier, builds a full-rect `ProductionGameplayHost` (`auto_build=false`), `build()`, waits one `process_frame` (layout frame), then `play_on_host`. `verify()` loops the dts; `search()` is the node-budgeted backtracking search and calls `play_level` / `verify`. Statuses: `SOLVED` (+`robust`), `UNWINNABLE_WITHIN_BUDGET`, `EXHAUSTED`.
- `scripts/gameplay/runtime/production_gameplay_host.gd`: with `app_state == null` (the "no-AppState debug/test harness path", `build()` ~l.236-264) the host uses its exported `level_path` and `supply_plan_path` directly; `LevelLoader.load_from_path(level_path)` (`scripts/data/level_loader.gd`, also `load_from_text`) validates the level, `_make_supply` calls `SupplyPlanLoader.load_engine(path, lvl)` (`scripts/gameplay/supply/supply_plan_loader.gd`: `load_plan`, `build_engine`, `load_engine`) and sets `_build_error` (`get_build_error()`) on failure. This is the existing way to build a host without the catalog.
- `tools/real_play_verify.gd`: catalog-only tool (`--levels`, `--regen`); writes plans/provenance only with `--regen`. Leave its behaviour untouched.
- `data/levels/supply/real_play_provenance_v1.json` holds `originalIntendedColumnClicks` for regenerated levels (L22 `level_022_crab`, plan under `data/levels/supply/`); `tests/real_play_levels.gd` has `OLD_L22` and a `search_negative` case showing the pre-080 L22 clicks are stuck and the search finds a robust order. Test style reference: that file (SceneTree, `_ok`, `EXPECTED_CASES`, final PASS line).
- CI list of suites and the exact-count guard: `.github/workflows/android-family-first10.yml` (~l.48, 132, 268). Docs: AGENTS.md l.18, `docs/10_LEVEL_FACTORY_GENERATION_SCORING_ARCHITECTURE.md` section 24.

## Requirements
1. New tool `tools/real_play_file.gd` (small sibling; do not bloat `real_play_verify.gd`). Usage string, exactly, printed on bad usage and documented verbatim:
   `godot --headless --path <ScrubBots repo> -s res://tools/real_play_file.gd -- --level-file <abs level.json> --plan-file <abs plan.json> [--search] [--out <abs result.json>]`
2. In `real_play_driver.gd` generalise the host-build path minimally so catalog play and file play share one code path (same full-rect parent, same one-layout-frame wait, same `play_on_host`, same human policy, same dts). Suggested: `play_level`/`verify`/`search` accept either an entry id String (unchanged behaviour) or a file source Dictionary `{level_path, supply_plan_path}` that builds the host with `app_state = null`, `auto_build=false`, `level_path`, `supply_plan_path`. Catalog results (tests/real_play_levels.gd, provenance) must be byte-for-byte unaffected. File mode never registers anything in `LevelCatalog`.
3. Input validation (all produce verdict `INVALID_INPUT`, exit 2, a JSON result with `error` text, never a crash/script error): missing/duplicate/unknown args; a path that is not absolute or starts with `res://` / `user://`; file missing/unreadable; level rejected by `LevelLoader` (use its validation result text); plan rejected by `SupplyPlanLoader.load_engine(plan, level)` (including levelId/colour mismatch it already checks); plan with no `intendedColumnClicks` array of ints (a plan to verify must carry clicks; empty array is INVALID_INPUT); `--out` that resolves inside the repo (`ProjectSettings.globalize_path("res://")` prefix, normalised) or whose parent dir is missing. If the `--out` path itself is unusable, still print the result line and exit 2.
4. Verdict logic (clicks = plan `intendedColumnClicks`):
   - play at every `SENSITIVITY_DTS`; all won -> `WON_ROBUST`;
   - won at 1/60 only (not all dts) -> `WON_CANONICAL_ONLY`; not won at 1/60 -> `LOST`;
   - with `--search` and verdict not `WON_ROBUST`: run `RealPlayDriver.search` (default `NODE_BUDGET`, from the plan's clicks). `SOLVED` + robust -> `WON_ROBUST` with `searched:true` and `searchedClicks`; `SOLVED` non-robust -> `WON_CANONICAL_ONLY` with `searchedClicks`; `EXHAUSTED` -> `SEARCH_EXHAUSTED`; `UNWINNABLE_WITHIN_BUDGET` -> `SEARCH_BUDGET`.
   - exit 0 iff final verdict `WON_ROBUST` (plan as given, or robust clicks found by `--search`); exit 1 for every other non-INVALID verdict; exit 2 for `INVALID_INPUT`.
5. Result JSON (pretty-printed with sorted keys to `--out` when given; also ALWAYS printed to stdout as the last line `REAL_PLAY_RESULT ` + single-line compact JSON, so callers can parse past Godot's banner). Fields: `schema: "scrubbots.real_play_file_result.v1"`, `model: "real_play_v1"`, `verdict`, `exitCode`, `searched` (bool), `levelFile`, `planFile`, `levelId` (from the plan, when valid), `planSha256` (`RealPlayDriver.plan_sha256` of the plan file as read; for INVALID_INPUT after the plan was readable still set, else null), `levelSha256` (same method), `gameCommit` (`git rev-parse HEAD` in the repo via `OS.execute`, else `"unknown"`; never fails the run), `planClicks` (ints), `perDt` (object keyed by `dt_label`: `won`, `frames`, `clicksPlaced`, `stuck`, `stuckClickIndex` (1-based index of the last click placed before it got stuck, null when won), `final` {active, supplyExhausted, slotsEmpty, terminal}, `slots` (slot state on failure: per-slot color/occupied/state taken from the host slots at the stop, null when won), `rejected`), `search` ({status, nodes, nodeBudget, robust, robustRejects} or null), `searchedClicks` (ints or null), `error` (string or null). Ints stay ints (no `1.0`).
6. Never write any file inside the repo in this mode: only `--out` (validated outside the repo) is written; no `--regen`-style edits, no provenance writes; temp artifacts (if any) only under `user://` and removed. The tool never edits the input level/plan files either (the caller rewrites clicks itself).
7. New suite `tests/real_play_file_cli.gd` (see acceptance). Add to the CI suite list (and keep the exact-count guard consistent) ONLY if its measured wall time is under about 3 minutes; otherwise leave it out of CI and state "local only, <measured> s" in AGENTS.md and the job's build notes.
8. Docs: AGENTS.md (extend the l.18 real-play line with the exact usage string, verdicts, exit codes, result schema id); `docs/10_LEVEL_FACTORY_GENERATION_SCORING_ARCHITECTURE.md` section 24 (new "File mode / Studio gate" bullet: contract table of verdicts and exit codes, result schema, "never writes in repo"); TASKS.md `SB-STUDIO-REAL-PLAY-GATE` game-side evidence note (scoped edit) pointing at the CLI and the Codex prompt.
9. Codex handoff: the builder MUST produce `factory/jobs/081-real-play-file-cli/CODEX_PROMPT_STUDIO_REAL_PLAY_GATE.md`, a complete, technically detailed prompt the owner pastes into Codex (Studio project at `C:/Users/sekip/Desktop/Scrubbots - Pixel Art Generator/Release/ScrubBots Factory Studio`, edited by Codex only). It must contain, self-contained (no references to our chat):
   a. Goal and rule: ProofKernel `SOLVED` + replay `WIN` alone must NO LONGER mark a candidate ready/shippable; the real-play CLI verdict is required in addition.
   b. Where to call: the Studio release-pool acceptance step (the point where a candidate becomes release-pool/"ready"); Codex must locate it in the Studio code and name the function it hooked.
   c. Exact CLI command (requirement 1), run via subprocess with argument list (no shell string), cwd irrelevant, timeout (suggest 900 s, configurable), capture stdout, parse the last `REAL_PLAY_RESULT ` line, also accept `--out` file; exit code semantics 0/1/2.
   d.    f. ## Out of scope
- Any edit to the Studio project or its files; Codex does that from the handoff prompt.
- Changing `real_play_v1` semantics, human policy, dts, `NODE_BUDGET`, the runtime, pacing or any level/plan/provenance data.
- Changing `tools/real_play_verify.gd` behaviour or the importer.
- Registering file-mode levels in the catalog, writing plans/provenance, a `--regen`-style mode, extra flags (`--dts`, `--budget`), a server/daemon, or a UI.
- Win/lose, economy, difficulty or ProofKernel changes.

## Assumptions
- Plan clicks are required (empty/missing is INVALID_INPUT): a file-mode caller always has Studio-produced clicks; the greedy no-plan path is catalog-only (Level 1).
- `WON_CANONICAL_ONLY` is a failing verdict (exit 1) even though it wins at 1/60: the driver's contract accepts a plan only if it wins at every sensitivity dt.
- `--search` also runs when the plan is `WON_CANONICAL_ONLY`, since a robust order may exist.
- Absolute filesystem paths only; `user://` and `res://` are rejected so results cannot be silently tied to the repo or a profile dir.
- `--out` inside the repo is rejected rather than allowed, to honour "never write inside the repo" literally.
- Generalising `play_level` to accept a file source is the smallest way to share the code path; the builder may pick an equivalent shape as long as the catalog behaviour is unchanged.
- stdout marker line `REAL_PLAY_RESULT <json>` is added because Godot prints its banner to stdout, making whole-stdout JSON parsing unreliable.
