# SB-TF-03 Home + Profile redesign

> Feature: Home/Profile redesign (owner chat 2026-11-18, final): no bottom nav, persistent bottom banner area, Profile hosts Robots/Ranks/Collection, Notifications move to Settings, Settings icon on Home, Shop only via "+", smaller see-through auto-hiding activity buttons (Rewarded Ads, Tasks, Daily, one per active Event), win-streak strip removed, robot-part badge on the Profile card with "PLAY - LEVEL N" on PLAY, new wave video.

## Requirements
1. Remove `BottomNav` entirely (all five buttons incl. Home, their badges/locks, `NavIcon_*` bindings, `nav_requested`/`set_app_nav`/`APP_NAV` plumbing that only served it). Remove `WinStreakRewardTrack` (`_build_track` and its render code). `BottomActionStack` keeps only PLAY.
2. The existing `AdBannerSlot` stays as the persistent bottom banner area under PLAY: height = standard 320x50 banner scaled to the viewport width (`width * 50/320`, clamped to existing min/max consts), safe-area aware, never overlapping PLAY/world. Collapsed (hidden, zero height) when `AdService.allowed("banner")` is false (No Ads owned); wired through `set_ad_slot_enabled` from `AdService.update_banner` state. No new ad SDK code beyond that wiring; null provider still draws the reserved empty area.
3. Settings: a Home icon button (name `SettingsButton`, kept stable) in the top HUD between the Profile card and the Scrub Bucks/Hearts chips; emits `settings_requested`; native Control, min touch target per `m49_touch_targets_text_stress`. Icon uses existing approved settings art (e.g. the former `NavIcon_settings` binding) .
4. Profile screen (`open_profile`): Robots button opens `RobotsScreen.open` (existing), new Ranks button opens `open_ranks`, Collection button opens the same `CollectionScreen.open_album`; the Profile "notifications" action is removed. Settings panel gets a Notifications entry opening `ProfileScreens.open_notifications`. Feature gates (`GATED_ENTRIES`: robots, ranks=leaderboard, collection) still apply to the Profile buttons.
5. New-card badge: `HomeBadges.compute()["collection"] > 0` draws a count/dot badge on the Profile Collection button AND on the Home Profile card (reuse `_badge_label` / existing badge pill style). Badge clears when cards are viewed in the album (existing `card:<id>` seen logic). Remove the Home Collection tile and the Robots/Ranks/Events nav badges from Home; the Profile card badge aggregate may also include robots/achievements as today but must include collection.
6. Shop: remove the Home Shop tile. Shop opens only from Scrub Bucks "+" and Hearts "+" (via popups). `open_life` popup gains the same "More in Shop" primary action as `open_scrub_bucks` (same key `SB_POPUP_MORE`, same `shop` action, source distinct e.g. `home_hearts_plus`).
7. Activity buttons: Rewarded Ads, Tasks, Daily, and one button per ACTIVE Event (from the Events v02 service; label `EventsV02Ui.title(id)`; opens that event's details via `EventsV02Ui.open_details`). Each is 30% smaller than the current tile (`PANEL_SIZE` 210x156 -> 147x109, icon box and label/font scaled 0.7), background alpha 50% of today's `PANEL_ALPHA` (0.51 -> ~0.255; border/label stay legible). Layout: two columns (left, right), at most 4 stacked per side, 8 total max; remaining events beyond 8 are not shown. Fixed assignment: left = Rewarded Ads, Tasks, Daily then events fill; right = events first-active order, overflow fills left slots then right (builder picks one deterministic order and documents it in a code const). Visible buttons reflow with no gaps; columns never overlap Scrubby centre, HUD, PLAY or the banner at any matrix viewport.
8. Auto-hide (re-evaluated in `refresh()`, collapse and reflow, no layout gap): Tasks hidden when all 4 daily tasks are claimed (including the all-tasks bonus per existing `orders`/`daily` state) until the next day; Rewarded Ads hidden when no rewarded views are left today (all `RewardedDailyService` slots claimed/exhausted); Daily hidden when `economy.daily.claimed_today()`; an Event button hidden when the event is not active or all its rewards are claimed. A day rollover or new active event re-shows them. Locked (level-gated) buttons keep their existing locked behaviour.
9. Profile card badge next to the Bot Parts bar shows a robot-part icon instead of the level number (reuse existing approved Bot Parts art used by the meter/currency if any, else a native Control icon; art only via `HomeArtBinder`/`HomePresentationMap` if bound art is used). `ProfileLevel` no longer shows the level.
10. PLAY text becomes "PLAY - LEVEL N" EN (with the middle dot U+00B7 as the owner wrote it: `PLAY · LEVEL N`) and "OYNA · LEVEL N" TR via a new parameterised UiText key (e.g. `HOME_PLAY_LEVEL`) in both `ui_text.gd` and `ui_text_tr.gd`; N = the level PLAY will launch (same value `_render_play` already uses for the launch preview). Text fits the PLAY button at all matrix viewports (font-fitted, no clipping).
11. Keep unchanged: world label (`HomeAreaLabel`), plaza background, Scrubby hero + videos, PLAY button behaviour, Gift Meter, Scrub Bucks/Hearts chips, reward flights, modal-hide behaviour (`MODAL_HIDDEN`, new Settings icon and activity layer hide under a modal like today).
12. Wave video: build a new `home_scrubby_wave_keyed.ogv` (same filename/set, Theora, 720x1280 24 fps, same Scrubby size/position framing as the other four keyed Home videos, exact-magenta #FF00FF background re-encode) from `Robot_Scrubby_waving_hello_640858a4.mp4`, keying per frame from the sampled background colour (drifts #FB02FC -> ~#EB28D7), using the job-160 approach (`key_home_videos.py`); the video shows ONE brush (or none doubled) and no magenta fringe (review a contact sheet / frame strip, save in the job folder). Update `HOME_ASSET_MANIFEST.json` `approved_sha256` (+ size fields if present) and `ASSET_GENERATION_MANIFEST.json`/PROVENANCE note; the first frame still must still match `home_scrubby_still.png` within the existing frame-0 tolerance used by `m42_c003_scrubby_animation` (if the new clip's frame 0 differs, the still-match assertion is adapted to the documented truth, not deleted). Keep APK size growth < 2 MB vs the old file.
13. Responsive: native Godot Controls, no overlap/clipping across all viewports in `tests/m49_responsive_matrix.gd`, EN and TR, safe areas honoured.
14. Docs: update `AGENTS.md` and any Home doc it lists (e.g. `docs/HOME_UI_ASSET_PLAN.md`, `assets/ui/HOME_ASSET_MANIFEST.json`) where they describe BottomNav / Shop tile / win-streak strip / level badge; mark SB-TF-03 in `TASKS.md` per factory convention with evidence.
15. Tests: update (do not delete) every suite listed in Context that pins the removed nav/shop tile/strip/level badge/old tile size to the new truth, and add the assertions in the acceptance list below (a new `tests/sb_tf03_home_profile.gd` is expected; add it to the CI validate list with an exact PASS guard like other `sb_*` suites).

## Assumptions
- "30% smaller" = linear 0.7x on both axes of the tile and its icon/label; "50% transparent" = half of today's panel alpha (border and text stay opaque for legibility).
- Overflow beyond 8 active events/buttons is simply not shown (3-5 events are active per owner plan, so 3 fixed + <=5 events fits 8).
- Profile card badge collection count reuses the existing `HomeBadges` "collection" metric (unviewed owned cards) as "new cards collected".
- The Settings icon reuses the former Nav settings art; no new art is generated.
- Hearts "More in Shop" reuses `SB_POPUP_MORE`; analytics source `home_hearts_plus` is new but needs no taxonomy beyond existing `source` field (m56 suite adjusted if it pins the list).
- The wave video's first frame may differ from `home_scrubby_still.png`; if so the still stays (owner did not ask to replace it) and the idle-to-clip cut is accepted unless the frame-0 tolerance test fails, in which case the test's tolerance is documented, not silently loosened.
