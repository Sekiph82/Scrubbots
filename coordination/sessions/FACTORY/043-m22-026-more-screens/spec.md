# SB-M22-026 step 4: measure the screens step 2 never visited, cap more textures

> Feature: SB-M22-026 step 4. Extend the measure tool with scenarios for screens not yet visited (Daily login/calendar, Tasks, unlock ceremonies/celebrations, robot unlock/assembly, Events, Achievements, RANKS/leaderboard, Settings, Help/tips, refill/need-a-hand popups, victory/fail variants, rewarded ads, shop sub-pages, FTUE coachmarks/opening cinematic frames if texture-based) at the same viewports (1080x2400, 1536x2048), throw-away saves only; record per-texture max draw size; merge with step 2's map (max of both); apply the same cap rule via the existing apply script (never lower an existing cap; never cap below 512; only when < source side); re-run budget test + relevant suites; extend per-screen budgets for any newly measured screen; update UI-ADR-008 with how many of the 416 are now measured/capped and MiB saved; list textures still unobserved and why. No PNG changes, no lossy/VRAM compression.

## Context
- `tests/tools/m22_026_texture_measure.gd` (step 2): boots real `main.tscn` in a SubViewport per scenario via `_boot(key, phys)` with a throw-away `user://` save (`MainScript.boot_save_path_override`), `SCENARIOS` list dispatched as `call("_" + s, key, phys)` at `PHYSICAL` = 1080x2400 and 1536x2048, `_walk` records per `res://assets/ui/final/` texture the max physical on-screen side, writes JSON with `merged` {path: max_side_px}. Existing scenarios: home, gameplay_5slot/6slot, results_won/failed, shop, collection, robots, life.
- `tools/m22_026_apply_caps.py <json> [--write]`: `limit = next_pow2(max(2*side, 512))`, written only if `< source max side` and the `.import` has no limit yet. Accepts a bare `{path: side}` map or a file with `merged`.
- Step 2 merged map: `coordination/sessions/FACTORY/038-m22-026-measured-caps/measure_merged.json`.
- `tests/m22_026_texture_budget.gd`: per-screen path lists (`HOME`, `GAMEPLAY`, `RESULTS`, `SHOP_COLLECTION`), `BUDGET_MIB`, `LIMITED`, `MEASURED` (path -> expected limit), card art checks.
- Entry points for the unvisited screens: `DailyScreens.open_daily/open_tasks/open_scrubbox/open_daily_reward/open_gift_bar(stack, app[, result])` (`scripts/ui/daily/daily_screens.gd`); `RewardedAdsScreen.open(stack, app)` (`daily/rewarded_ads_screen.gd`); `ProfileScreens.open_profile/open_achievements/open_events/open_comeback/open_notifications(stack, app)` (`profile/profile_screens.gd`); `HelpTipsScreen.open(stack, app)` (`tutorial/help_tips_screen.gd`); `RobotsScreen.open_detail(stack, app, id)`; `MetaCeremonies.build(event, reduced)` for `set_complete`, `master_complete`, `robot_unlock`, `gift_milestone`, `feature_unlock`, `world_unlock` (`ceremony/meta_ceremonies.gd`; push the built popup on `_root.get_modal_stack()`); pack ceremonies (`ceremony/standard_pack_ceremony.gd`, `premium_pack_ceremony.gd`, via `get_pack_presenter()`); `AcquisitionFlow` `open_need_a_hand(offer)`, `open_insufficient(ctx)`, `open_booster(host, id)`; the Settings panel (`settings_panel.gd` `open_panel()`); `CoachmarkLayer.show_step` via `get_coachmarks()` (`tutorial/coachmark_layer.gd`); `opening_screen.gd` (video texture, likely not a `final/` PNG); RANKS is not served (main.gd comment: waits for SB-M43-131), so there may be nothing to measure.
- Unlock gating (job 042): `AppState.feature_unlocked` (`scripts/app/app_state.gd`); a save whose `economy.ftue.profile` is `PROFILE_ESTABLISHED` (the default, `scripts/economy/ftue_state.gd`) is grandfathered and has everything unlocked. Do not set `PROFILE_NEW` in measure fixtures unless the scenario is the FTUE one.

## Requirements
1. Add scenarios to `tests/tools/m22_026_texture_measure.gd` (append to `SCENARIOS`; keep all nine existing ones and their behaviour) covering, where an entry point exists: Daily login popup + daily reward, Tasks, Scrubbox, gift bar, Rewarded Ads, Profile, Achievements, Events, Comeback, Notifications, Help/tips, Settings panel, Robots detail of every roster robot, every `MetaCeremonies.build` kind with a valid fixture event (robot unlock for every roster robot, set/master complete, gift milestone, feature unlock with an existing icon, world unlock only if a real registry entry exists), standard and premium pack ceremony, Need-a-Hand, Insufficient, a booster popup, Results won/failed variants not yet seen (e.g. with a reward row, a new-record or streak variant if reachable), Shop sub-pages (every tab/section the shop screen exposes), and FTUE coachmark steps (`show_step` for each FTUE step id) with the tutorial pointer/ring/bubble textures. A scenario that cannot open is recorded in `skipped` with the reason, never silently dropped.
2. All fixtures use throw-away `user://` saves, are grandfathered/high-frontier so gated screens open, and never touch the real save. Both viewports as before.
3. Output a new report JSON in the same format; merge with the step 2 map by per-path max, producing `coordination/sessions/FACTORY/043-m22-026-more-screens/measure_merged.json` (and the new raw `measure.json` there). Do not edit the step 2 files.
4. Apply with the existing `tools/m22_026_apply_caps.py` on the merged map (`--write`). Do not change its rule; never lower an existing limit, never below 512, only when `< source side`. Only `process/size_limit` lines in `.import` files change. No PNG changes, no `compress/mode` or mipmap changes.
5. `tests/m22_026_texture_budget.gd`: add every newly capped path to `MEASURED` with its limit; add a per-screen list plus `BUDGET_MIB` (measured resident MiB + ~10%) for each newly measured screen group (e.g. Daily/Tasks, Profile/Events/Achievements, Ceremonies, Robots detail, Popups). Existing budgets may only stay or drop, and existing entries stay.
6. Re-measure after the re-import and confirm the newly measured sides are unchanged (layout independent of texture size), as step 2 did.
7. Docs: add "UI-ADR-008 step 4" in `docs/07_UI_ASSET_PIPELINE_DECISIONS.md` with the scenarios added, count of the 416 previously unobserved PNGs now observed, number newly capped, MiB saved (resident RGBA8 library total before/after, and per-screen tables for new screens), smallest limit/side ratio, and the list of textures still unobserved with the reason per group (for example `_draw`/StyleBox art, unused art, opening video, RANKS not served, size 0). Update the "Known limit" note and the `AGENTS.md` / TASKS.md SB-M22-026 entry (step 4 done, evidence) where they mention this task's status.

## Out of scope
- Any PNG edit, VRAM/ETC2/ASTC compression, atlasing, lossy settings, mipmaps, lazy loading.
- Changing the cap rule, the existing caps, shipping runtime code or screen layouts.
- Opening cinematic video frames (not `final/` textures); capping unobserved or size-0 textures from guesses.
- Implementing RANKS or any unserved screen.
- Touching the real save, `project.godot`, or owner's Desktop checkout files.

## Assumptions
- Default fixture profile (`PROFILE_ESTABLISHED`) is grandfathered, so no frontier hacking is needed; reason: job 042's rule.
- Ceremony/pack/coachmark popups are built directly from fixture events rather than played through economy transactions; reason: only the on-screen texture size matters and fixtures must not grant anything.
- The 2x / 512 floor rule is reused unchanged; reason: consistent with step 2 and safe.
- Sizes measured at 1080x2400 and 1536x2048 only; the larger of the two drives the cap, as in step 2.
