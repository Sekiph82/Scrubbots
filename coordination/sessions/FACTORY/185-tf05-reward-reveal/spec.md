# Shared reward reveal (1.5 s hold, then fly) + rewarded x2 Scrub Bucks on win

> Feature: SB-TF-05 — owner 2026-11-18: "Bütün ödül uçuşları. ekranda bekleme suresi 1.5 saniye olsun." One shared reward-reveal used by ALL reward sources (level win, Tasks, Daily, Gift meter, Events, Rewarded Ads, Shop purchases, collection sets): every reward appears at once, holds 1.5 s, then flies to its target (currency chip / profile card etc.); all buttons/input locked until the flight ends. Card packs start from this screen: card grows, then the existing pack-opening video. After a level win, during the 1.5 s hold, a rewarded "Watch ad, x2" button doubles only the Scrub Bucks of that win on a verified completed view (economy service grant, idempotent per receipt, cannot double twice); no ad / skipped / failed -> normal reward, flight starts at once; while the ad plays the hold pauses; No Ads still allows rewarded; ad test mode respected. Reduced Effects: reveal still shows, flight simplified/instant.

## Context
- Today only a level win has a reward flight: `scripts/ui/home/home_reward_flight.gd` (`HomeRewardFlight`, built from the committed `TerminalRewardReceipt` via `plan(receipt, vm)`; fade-in "+N" at screen centre, then `min(N,5)` staggered copies fly `FLY_S`=0.5 to the HUD target; counters via `home.show_hud_value`; full-rect `RewardFlightLayer` swallows input; one-shot per key through `scripts/ui/components/reveal_sequencer.gd`; Reduced lands the final state at once). Entry: `home_screen.gd` `play_reward_flight` / `is_reward_flight_running` / signal `reward_flight_finished`; `scripts/app/main.gd` `_start_win_rewards` (key `win:a<attempt>:L<level>`), `_drain_home_ceremonies`, `_drain_earned_packs` (both wait while a flight runs).
- SB-TF-03 removed the Home win-streak strip: there is no win_streak flight target (streak SB just lands in the wallet). Collection lives in Profile: cards fly to `ProfileCard`. Targets known to `home.get_region`: `ScrubBucksChip`, `ProfileBotParts`, `GiftMeterBar`, `ProfileCard`.
- Other sources today show their own popups / ceremonies, no flight: Tasks and ScrubBox, Daily login (`scripts/ui/daily/daily_screens.gd`, `app.actions.claim_daily_task / claim_daily_all_tasks / claim_daily_login / claim_gift`), Events (`scripts/ui/events/events_v02_ui.gd`, `claim_event_milestone / claim_event_reward`), Rewarded Ads (`scripts/ui/daily/rewarded_ads_screen.gd`, `scripts/economy/rewarded_grant_service.gd`), Shop (`ProductionActionFacade.buy_*`, store/IAP grants), collection set / master / gift milestone ceremonies (`scripts/ui/ceremony/meta_ceremonies.gd`, `ceremony_presenter.gd`), earned packs (`scripts/ui/ceremony/standard_pack_ceremony.gd`, `premium_pack_ceremony.gd`, `packs.drain()`).
- Economy truth: `ProductionActionFacade` + `scripts/economy/*` grant under idempotent tx ids; UI Controls never mutate economy (CLAUDE.md, OWNER_ECONOMY_REWARDS_V01 section 480). `RewardedGrantService.resolve` commits only `outcome == "completed"` AND `verified == true`, via `RewardGrantService.grant(tx, rewards)`; `AdmobAdProvider.request(placement, token, deliver)` delivers `verified = earned` on close; `StoreService.ads_allowed("rewarded")` stays true under No Ads. Its header says "no rewarded 2x" (that refers to the old product list and must be updated, see requirement 14).
- Terminal receipt: `scripts/economy/terminal_reward_receipt.gd` (`wallet_delta.scrub_bucks`, committed before the win animation; the win SB are already in the wallet when Home appears).

## Requirements
1. New shared presenter `scripts/ui/components/reward_reveal.gd` (class `RewardReveal`, RefCounted/Control layer, presentation only; reuse `RevealSequencer`, `UiText`, existing icons from `HomeRewardFlight.ICONS`). API: `show_rewards(entries: Array, key: String, opts: Dictionary) -> bool` where an entry is `{kind, n, from, to, target}` (same shape as `HomeRewardFlight.plan`); signals `completed(key)`. It never grants, saves or reads economy.
2. Timeline per call: all entries appear TOGETHER in one frame/fade (<= `APPEAR_S` 0.12 s, not one after another), then a hold of exactly `HOLD_S = 1.5` seconds (a const, measured from the reveal being fully shown), then the existing fly (staggered copies, `FLY_S`) to each entry's target, counters stepping to exact final values. Total input lock from reveal start to the last arrival.
3. Input lock: a full-rect `MOUSE_FILTER_STOP` layer that also blocks Back / Android back / ModalStack opening and swallows every tap (same as the existing `RewardFlightLayer` rule) for the whole reveal + flight; freed on completion, `finish()`, Reduced, or the existing safety timeout (must be >= hold + flight + ad time; not shorter while an ad is playing). A reveal with zero entries shows nothing and never locks.
4. Reduced Effects (existing reduced-effects flag path used by `HomeRewardFlight.play(..., reduced)`): the reveal still shows and holds `HOLD_S`, but the flight is skipped/instant (final counter values applied at once, no copies, no pickup feel). The hold is not removed by Reduced.
5. One-shot per key: replaying the same key does nothing (RevealSequencer semantics); a relaunch never replays a reveal.
6. `HomeRewardFlight` is retired as the win path: it keeps its `plan()` receipt mapping (reuse, or move into the shared presenter) but the win now calls the shared reveal. `home_screen.play_reward_flight`, `is_reward_flight_running`, `reward_flight_finished` keep working (main.gd drains and gates keep their meaning) and are wired to the shared reveal.
7. Every source routes through the shared reveal, built from the COMMITTED result the facade returned (never recomputed): level win (receipt), Tasks claim + ScrubBox, Daily login claim, Gift meter milestone claim (`claim_gift`), Events (`claim_event_milestone`, `claim_event_reward`), Rewarded Ads (heart/booster/daily slot grants), Shop purchases (SB bundles, Hearts, boosters, entitlements that grant visible rewards), collection set / master complete rewards. A single central entry (e.g. `main.gd` `request_reward_reveal(source, entries, key)` reachable from popups via a signal/Callable like `request_earned_packs`) is used; popups do not build their own flights. The old per-source reward celebration popups that merely repeated the same reward lines are replaced by the reveal; ceremonies with story art (robot unlock, feature unlock, world, featured card) are unchanged and still queue AFTER the reveal.
8. Reward kinds shown: scrub_bucks, bot_parts, hearts, boosters (per id icon), gift_meter progress, collection cards / packs. Targets: currency chip / HUD region where one exists; otherwise (hearts, boosters, cards, anything without a HUD node) the profile card or the Hearts chip as in the current Home layout; a missing target falls back to flying nothing but still holds and counts. No win_streak target (SB-TF-03).
9. Card packs: an entry of kind pack starts the reveal as a card/pack icon that GROWS during the hold (scale tween, still within the 1.5 s), then instead of flying it hands to the existing earned-pack flow (`packs.drain()` -> standard/premium pack ceremony and its opening video) exactly once. The pack-opening video code is not changed.
10. Rewarded x2 button (win only): while the win reveal's 1.5 s hold runs, a "Watch ad, x2" native Button (new `UiText` keys in EN and TR) is shown only if the receipt has `wallet_delta.scrub_bucks > 0`, the reveal source is the win, and `RewardedAdProvider.is_available("rewarded_win_double")` is true. Not shown for any other source, for LOST, or when no ad is ready (then the reveal is the plain 1.5 s hold, or per owner rule "flight starts at once" only when an ad was attempted and failed).
11. x2 flow: tapping pauses the hold timer (the clock does not advance while the ad plays), calls the provider through the existing `RewardedGrantService` path with a new product `win_double:<receipt_key>` (placement `rewarded_win_double`); a granted result adds EXACTLY the receipt's Scrub Bucks again (one extra `wallet_delta.scrub_bucks`, so total x2; bot parts, gift meter, cards, streak bonus unchanged) via `RewardGrantService.grant` with deterministic tx id `win_double:<receipt_key>` persisted by the M40 save, so duplicate / late / relaunched callbacks and a second tap grant nothing (cannot double twice). Granted on `completed` AND `verified == true` only. The reveal then shows the doubled "+N" and the flight counts to the doubled wallet. Skipped / failed / unverified / timeout / unavailable: no grant, the hold is abandoned and the flight starts at once with the normal amount. After the tap or a result the button is gone. The grant is requested through `ProductionActionFacade` / the service, never by a Control touching the wallet.
12. Respect ads rules: x2 is shown and works under No Ads (`StoreService.ads_allowed("rewarded")` stays true); ad test mode (SB-TF-01 test ad ids) uses the same path, no special casing in the reveal. `ads_cadence`: a rewarded view does not count as an interstitial play.
13. Timing and clock must be injectable: the presenter takes its timers from a replaceable clock/`Callable` (or is driven by `advance(dt)` in tests) so the suite can use a fake clock; no wall-clock dependence, no `await get_tree().create_timer` that tests cannot advance.

Docs: add a short dated amendment to `coordination/OWNER_ECONOMY_REWARDS_V01.md` ("Owner 2026-11-18: rewarded x2 Scrub Bucks after a level win; doubles only that win's Scrub Bucks; once per win; granted only on a verified completed view; no free manual speed 2x is introduced - the section 7 speed 2x is unrelated") and fix the "no rewarded 2x" wording in the `rewarded_grant_service.gd` header, add the new product to its products note. Update `docs/MASTER_UI_SYSTEM.md` (or the doc that currently describes the Home reward flight) and `AGENTS.md` where they describe reward flights / the Home flight lock, and the analytics taxonomy `source` enum only if a new reward source value is needed (`rewarded_ad` exists; add `win_double` only if the win_double grant is emitted as an analytics grant event). Mark SB-TF-05 in TASKS.md per the factory loop.
15. No new economy numbers: 1.5 s, FLY_S, STAGGER_S are UI constants; x2 is exactly one extra copy of the win's SB; there is no cap, cooldown or price invented.

## Assumptions
- "Holds 1.5 s" is measured from the reveal fully shown to the first flight departure; the hold is the same for Reduced Effects (only the flight is shortened), because the owner asked for a fixed wait and Reduced rules only cover motion.
- The ad button appears only if an ad is ready; if the ad was attempted and fails, the flight starts immediately (owner wording); with no ad ready there is simply no button and the normal 1.5 s hold plays.
- The win's Scrub Bucks are already committed in the wallet when Home appears; x2 therefore grants an additional equal amount under its own deterministic tx id keyed by the win receipt key (attempt + level), which is what makes it idempotent and un-doublable.
- The streak-bonus Scrub Bucks in the receipt's `wallet_delta.scrub_bucks` count as part of "the Scrub Bucks of that win" (the receipt number is the single source), no separate splitting.
- Where a reward has no HUD node (hearts, boosters, cards) it flies to the nearest existing Home chip / profile card; no new HUD elements are added.
- The economy doc needs a short owner-amendment note because its "rewarded ads are separate M57 decisions" line and the service's "no rewarded 2x" header would otherwise contradict the shipped feature; the owner statement is the 2026-11-18 chat, recorded as such. This is not a section 0D.5 escalation item.
