> Feature: SB-TF-07 (owner chat 2026-11-18). ## Assumptions

- "Level 10 / level 20": interstitial counts plays whose finished level is >= 10 (the level just played); App Open uses the progression frontier (`current_level()`) >= 20. Reason: matches "after the player has reached level 20" and keeps the gate based on saved progress.
- Plays before level 10 do not bank toward the first interstitial (first ad needs 4 plays at level >= 10). Reason: avoids an instant ad on arriving at level 10, closest to "none before 10, then every 4".
- "Install day": no install date is stored, so AdService records the first launch day of the profile (`first_day`); an existing player updating gets "install day = update day", which only delays their first App Open by one day. Reason: smallest conservative default, no fake date invented.
- "Day" is the local-calendar day already used by Daily / Rewarded Daily (`economy.daily.local_day`), not UTC. Reason: reuses the existing clock-rollback-safe concept.
- "Once per event per day" is per event instance (`<event_id>:<cycle>`) per local day; instances of different events are independent. Reason: instance id is the unit the events service and saves already use.
- The event +1 is hidden for `quest` and `colors` events because their progress is derived (objectives from other events / cleaned pixels per colour) and a manual +1 cannot be represented without a new mechanic. The owner request said "each active event screen"; this is the only conservative reading. Flag this in the final report for the owner.
- The ad requires the player to have joined the event (progress only counts for joined instances today). Reason: preserves "no retroactive / unjoined progress".
- If the event window ends while the ad is playing, the verified view is consumed with no progress (handler no-op). Reason: rare edge, avoids a second ledger.
- App Open real-id units do not exist yet: release builds simply show none until `app_open` ids are provided (one question line in TASKS.md); test builds show Google test App Open ads. Reason: no new required secret may break release builds; no spending decision is made here.
- Analytics taxonomy stays at `version: 1` with additive enum/event (m56 pins version 1); the new event carries task `SB-TF-07`.
