# Achievements earned-first order + Collection "Read all"

> Feature: Owner request (2026-11-18): "achievementsda kazanilan achievementslar en ustte olacak sekilde acilabilir mi? bir de koleksiyon da yeni acilan her karti tek tek okumak yerine read all gibi bir tusla tum okunmayan yeni kartlarin okunmasini saglayabilir miyiz?" (SB-TF-08: Achievements list opens with earned achievements on top, claimable first, then claimed, then in progress; Collection gets a "Read all" / "Tümünü oku" button that marks every unread new card seen at once, all new badges clear, no reward change.)

## Context
Achievements:
- `scripts/progression/achievements.gd` `Achievements.evaluate(app)` returns the 50 data-driven entries in catalogue (definition) order, each with `done`, `claimed`, `claimable` (`claimable = done and not claimed`). `claimable_count(app)` feeds `HomeBadges.compute()["achievements"]`. Claim goes through `ProductionActionFacade.claim_achievement` (`scripts/economy/production_action_facade.gd`, `_finish_durable`).
- `scripts/ui/profile/profile_screens.gd` `open_achievements(stack, app)` builds a `BasePopup("achievements")` with `AchSummary` and a `ScrollContainer` named `AchievementList` (a `VBoxContainer` of `Ach_<id>` cards from `_ach_card`), iterating `ach` in catalogue order. CLAIM buttons are `p.add_action("ach:<id>", ...)` attached into each card's `Right` node; after a successful claim the card is turned into the COMPLETED pill in place (no reordering today).

Collection:
- `scripts/ui/collection/collection_screen.gd`. "New card" = owned > 0 and not `economy.meta_ui.is_seen("card:<id>")` (`card_key`, `unseen_cards(economy)`). Today a card is only marked seen when its set detail is opened: `open_set` calls `e.meta_ui.mark_seen(card_key(cid))` per owned card and then `app.mark_dirty()` (flushed at the next lifecycle boundary). `_refresh_album(p, e)` shows a per-set `NewBadge` count; `open_album` builds the header (`Summary`, `PackRow` with `packs` action, `exchange` action, `SetList`), and `_on_album_action` dispatches `packs` / `exchange` / `set:<n>`.
- `HomeBadges.compute(app)["collection"]` (`scripts/ui/home/home_badges.gd` lines ~65-67) counts owned cards not seen; the Profile Collection button badge (`CollectionBadge`, `_render_destination_badges` in `profile_screens.gd`, SB-TF-03) and the Home profile badge sum read from it, so they clear automatically once the `card:<id>` marks exist.
- Seen state: `scripts/economy/meta_ui_state.gd` (`MetaUiState.is_seen/mark_seen/seen_keys`), part of the canonical EconomyServices snapshot (section `meta_ui`), so it is saved with `app.request_save()`.
- Facade pattern for state-changing actions: `ProductionActionFacade` methods wrap a service call in `_finish` / `_finish_durable` (save + rollback on failure).

Existing suites touching these areas: `tests/sb_tf03_home_profile.gd`, `tests/m43_master_c010_meta.gd`, `tests/m44_meta_verify_achievements_gift.gd`, `tests/m44_new_badge.gd`, `tests/m43_master_c007_collection.gd`, `tests/m54_collection_set_master_exactly_once.gd`, `tests/m22_028_collection_card_lru.gd`, `tests/m47_touch_r01_mobile_ux.gd`, `tests/m49_surface_matrix.gd`, `tests/m49_surface_stress.gd`, `tests/m50_accessibility_audit.gd`, `tests/m51_localization_readiness.gd`.

## Requirements
1. Achievements order: when the Achievements popup opens, the list is ordered in three groups: (a) claimable (done, reward not claimed), (b) claimed (done and claimed), (c) in progress (not done). Inside each group the relative order is the existing catalogue order (stable). Implement as a pure, static helper (e.g. `Achievements.sort_for_display(list: Array) -> Array` in `scripts/progression/achievements.gd`) taking the `evaluate()` output; `evaluate()` itself and `claimable_count()` keep returning catalogue order.
2. The list opens scrolled to the top (`AchievementList.scroll_vertical == 0` after the popup is shown/opened).
3. Claiming in the open popup keeps the current in-place card behaviour (no reorder or scroll jump mid-session); the new order applies the next time the popup opens. Rewards, claim flow and `claim_achievement` are unchanged.
4. Collection service operation: add a method on the Collection-side meta state (preferred: `MetaUiState.mark_all_seen(keys: Array) -> int`, returning the number newly marked) and a facade action `ProductionActionFacade.mark_all_cards_seen()` (via `_finish_durable`, so it is one persisted save with rollback on save failure) that marks `card:<id>` seen for exactly the cards in `CollectionScreen.unseen_cards(economy)` (owned > 0 and unseen). Returns `{ok, marked}`. It never touches inventory, rewards, packs, ownership counts, pity or set/master claim state, and is idempotent (second call: `marked == 0`). The UI must call this action and must not call `meta_ui.mark_seen` itself. If the facade cannot reach the save (no host), follow the existing `_finish` semantics.
5. Collection UI: a button named `ReadAll` (action id `read_all`) in the Collection album, shown only while at least one unread new card exists (`unseen_cards(...).size() > 0`), hidden otherwise (including when the album opens with none). Style `secondary`/`primary` per the existing `add_action` pattern, placed in the header area (e.g. next to the Pack row / above `SetList`), minimum height `UiTokens.TOUCH_MIN`, label fits without clipping in both languages at the 1080x2160 baseline.
6. Pressing it calls the facade action once, then `_refresh_album` so: every per-set `NewBadge` is hidden, `ReadAll` hides, and `p.rearm()` is called like the other actions. After close, the Profile Collection button badge and the Home profile badge sum no longer count cards (`HomeBadges.compute(app)["collection"] == 0`, `CollectionBadge` hidden); no other badge (achievements, robots, tasks...) changes. The existing per-set auto-seen behaviour in `open_set` stays. The `ReadAll` visibility is also re-evaluated by `_refresh_album` (it runs again when the album is back on top after a pack opening that granted new cards, so the button reappears).
7. Persistence: the seen marks survive snapshot/import and a reload (`meta_ui.snapshot()` contains all `card:<id>` keys after Read all).
8. Text keys, EN in `scripts/ui/ui_text.gd` and TR in `scripts/ui/ui_text_tr.gd`, same key set in both (the `m51_localization_readiness` parity rule): `COLLECTION_READ_ALL` = "READ ALL" / "TÜMÜNÜ OKU" (match the casing of neighbouring button keys such as `COLLECTION_OPEN_EXCHANGE` / "KART TAKASI"). No new key for Achievements (no UI text added there).
9. Docs: add a done line under SB-TF-08 in `TASKS.md` (both Autonomous Queue line 16 and section entry ~line 280) with honest evidence labels (`LOCAL_PASS`, no invented CI run); mention the two behaviours in any doc the repo already keeps for these screens if one exists (grep `docs/` for "Achievements" / "Collection" screen specs; update only if a matching statement would become wrong). Add the new suite to the CI validate list and a PASS-line guard in `.github/workflows/android-family-first10.yml` (same pattern as the SB-TF-07 guard at the `AD-PLACEMENTS` block).
10. New suite `tests/sb_tf08_achievements_readall.gd` (extends SceneTree, same style/boot helpers as `tests/sb_tf03_home_profile.gd`) printing the exact line `SB-TF-08 achievements order + collection read all evidence: PASS (12/12 cases, 0 fail)` (case count must equal the number of cases actually run; adjust "12/12" to the real count if it differs and keep the CI guard string identical).

## Acceptance criteria
Run each with `"$GODOT" --headless --path <worktree> -s res://tests/<suite>.gd`.
1. `sort_for_display` on a fixture with mixed states returns claimable, then claimed, then in-progress, each group in original catalogue order; input list is not mutated; empty list and all-in-progress list work. (suite case)
2. Opening the real Achievements popup with a fixture where an entry late in the catalogue is claimable and an early one is in progress: the first `Ach_*` child of `AchievementList`'s list is the claimable one, the claimed ones follow, the in-progress ones last; node order under the VBox matches `sort_for_display`. (suite case)
3. `AchievementList.scroll_vertical == 0` after opening, even when the fixture has 50 entries. (suite case)
4. Claiming a card in the popup still works (CLAIM button grants once, card shows the COMPLETED pill, `HomeBadges.compute()["achievements"]` drops by 1) and no card is re-parented during the session. (suite case)
5. Album with zero unread cards: no visible `ReadAll` button. With 3 owned unseen cards in 2 sets: `ReadAll` visible, set `NewBadge` labels show the counts. (suite cases)
6. Pressing `ReadAll` (via the real action path, `p.action_selected.emit("read_all", ...)` or pressing the button): `CollectionScreen.unseen_cards(economy).is_empty()`, `meta_ui.is_seen("card:<id>")` is true for all 3, all `NewBadge`s hidden, `ReadAll` hidden, `HomeBadges.compute(app)["collection"] == 0`. 7. Read all changes nothing else: economy snapshot equals the pre-press snapshot except the `meta_ui.seen` list (scrub bucks, bot parts, packs, collection counts, applied tx ids identical); a card not owned is NOT marked seen. (suite case)
8. Idempotent: second facade call returns `{ok: true, marked: 0}`. (suite case)
9. Persistence: after Read all, `economy.snapshot()` -> new EconomyServices `import_snapshot` -> `is_seen` still true for the cards; `HomeBadges.compute` still 0. If the save callback fails, the state is rolled back and cards are still unread (use the existing `_save_cb` failing-harness style from other facade tests). (suite cases)
10. Profile: with unread cards, the Profile popup's `CollectionBadge` is visible with the count; after open Collection -> Read all -> close, `_render_destination_badges` hides it, and the Home profile badge no longer includes collection cards. (suite case)

12. Accessibility/layout: `ReadAll` is >= `UiTokens.TOUCH_MIN` high and its rect lies inside the popup interior at 1080x2160 in EN and TR (no clipped text: label minimum size <= button size); `ui_text` EN/TR both define `COLLECTION_READ_ALL`. (suite case)

## Out of scope
- Reordering or editing the achievement catalogue (`achievements_v2.json`), rewards, targets, tiers, or the claim flow; auto-claim; live re-sorting while the popup is open.
- Any change to rewards, pack contents, pity, set/master claim rules, or the exchange screen.
- A "Read all" for other badge families (robots, events, tasks), or marking card detail views differently.
- New art, new badges, new animations/sound for the button; changing the per-set `NewBadge` visuals.
- Building APK/IPA or phone builds (batching rule); touching `TASKS.md` beyond the SB-TF-08 evidence lines.

## Assumptions
- "Earned" at the top = claimable first, then claimed (matches the TASKS.md entry and owner request wording); in-progress last, no sorting by progress percentage (keeps catalogue order, the conservative choice).
- The order applies on open, not live, so a tap on CLAIM never moves the card under the player's finger.
- Read all marks only OWNED unseen cards (same set as the badge counts), so unowned cards are not pre-marked and will still show NEW when later obtained.
- The seen marks live in the existing `meta_ui` section; no save-format version change is needed because only already-valid `card:<id>` keys are added.
- Button label is placed in the Collection album header (not per set) and uses secondary styling; exact placement is the builder's call as long as it is in the always-visible header, not inside the scrolling list.
- Suite case count of 12 is a target matching the criteria above; the builder may split/merge cases but must keep the printed line and the CI guard string consistent.
