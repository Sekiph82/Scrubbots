# SB-M22-026 step 2: runtime-measured size_limit caps

> Feature: SB-M22-026 step 2. Add a headless Godot tool that measures the real on-screen size of every texture on Home, Gameplay (5-slot and 6-slot), Results, Shop and Collection at the largest supported portrait viewport (and tablet 1536x2048), using throw-away saves. Cap rule: size_limit = next power of two >= max(2 x measured max side, 512), only when below the source max side; never below 512; unobserved textures untouched. Apply caps, re-import, tighten the per-screen budgets, rerun the suites, update UI-ADR-008 with before/after per screen. Owner art PNGs immutable; only .import size_limit changes; no lossy/VRAM compression.

## Context
- Step 1 (factory job 037, `coordination/sessions/FACTORY/037-m22-026-texture-budgets/build.md`) capped only 5 icons (-0.76%) because most draw sizes are not literal in code. Per-screen resident RGBA8 today: Home 207.07 MiB (88 textures), Gameplay 50.72 (17), Results 65.99 (11), Shop/Collection 69.99 (15).
- `tools/m22_026_texture_inventory.py` (static, stdlib) and `tests/m22_026_texture_budget.gd` (per-screen path lists `HOME`, `HOME_FRAMES`, `GAMEPLAY`, `RESULTS`, `SHOP_COLLECTION`, `BUDGET_MIB`, plus the 5 cap checks) and `docs/07_UI_ASSET_PIPELINE_DECISIONS.md` UI-ADR-008 exist. Boosters are already capped at 512 (UI-ADR-007, `tests/m22_025_booster_texture_budget.gd`, 12 MiB).
- The repo tracks `.import` files only for the 10 boosters plus the 5 step-1 icons; other `.import` files are untracked Godot output. Capped textures therefore become new tracked `.import` files (same as jobs 034/037).
- Fixture pattern to reuse: `tests/m28_c002_c001_gameplay_v02.gd` `_boot` (SubViewport + `MainScript.boot_save_path_override = "user://...save"` + `MainScene.instantiate()` + `play_current_frontier()`; override reset and temp save removed afterwards). Viewport matrix: `tests/m49_responsive_matrix.gd` (`PHYSICAL` includes 1080x2400 and 1536x2048; logical size from `_logical`, so physical px = logical rect x phys/logical).
- Existing tools live in `tests/tools/` (e.g. `gameplay_v02_final_snapshot.gd`, `collection_snapshot.gd`, `daily_snapshot.gd`) and show how to reach Shop/Collection/Results from `main.tscn`.

## Requirements
1. New `tests/tools/m22_026_texture_measure.gd` (`extends SceneTree`, headless, run with `-s`). For each scenario below it boots `main.tscn` in a SubViewport at the given physical size with a unique throw-away `user://` save via `boot_save_path_override` (never the real save; override reset and save files deleted at the end), lets it settle a few frames, then walks the whole subtree (including nodes outside the visible tree children such as popups under the scene root) and for every `TextureRect`, `NinePatchRect`, `TextureButton` (normal/pressed/hover/disabled textures) and `Sprite2D` whose texture has a `res://assets/ui/final/` `resource_path` (unwrap `AtlasTexture` to its atlas path and count the full atlas file) records: the visible-or-not node's `get_global_rect().size` (Sprite2D: texture size x global scale) multiplied by physical/logical scale; keeps the max side per texture path per scenario. Nodes with size 0 are skipped but their path is still listed as "loaded, size 0".
2. Scenarios: Home; Gameplay 5-slot; Gameplay 6-slot (Economy +1 Slot shell, reuse whatever `m49`/`m28` use to force six slots); Results (won and failed); Shop; Collection; each at 1080x2400, and again at 1536x2048. Also cycle Home through its Scrubby gesture frames so frame textures are seen. Each scenario also records the set of all textures loaded (the per-screen MiB at current limits, RGBA8 w*h*4 of the imported size).
3. The tool writes JSON `{scenario: {path: {max_side_px, max_w, max_h, source_w, source_h, size_limit}}}` plus a merged `{path: max_side_px over all scenarios}` map to the path given by user arg `--out=<file>` (default `user://m22_026_measure.json`; the job writes it to `factory/jobs/038-m22-026-measured-caps/measure.json`). The raw report is not committed to the repo; if small (< 100 KB) a trimmed merged map may be committed as `coordination/sessions/FACTORY/038-m22-026-measured-caps/measure_merged.json`.
4. Cap rule, applied by a second small script step (`tools/m22_026_apply_caps.py`, stdlib, reads the merged JSON, prints a table, `--write` edits `.import`): for each observed texture, `limit = next_pow2(max(2 * max_side_px, 512))`; set `process/size_limit=limit` only if `limit < max(source_w, source_h)`. Textures not observed in any scenario are untouched. Never lower an existing smaller limit (boosters 512, step-1 icons keep their value). Full-width/background art is covered by the 512 floor and by 2x of its measured side (it will not be capped below 512). Only the `process/size_limit` line in `[params]` changes; `compress/mode=0` and mipmaps off stay.
5. Run `--headless --import` after applying; PNGs unchanged.
6. Update `tests/m22_026_texture_budget.gd`: per-screen budgets tightened to measured-after + ~10%, a check for the new caps (each capped file's imported size <= its limit, alpha kept), and the 5 step-1 checks kept. Keep the existing path lists unless the measurement showed a texture missing from them (then add it and say so).
7. Update `docs/07_UI_ASSET_PIPELINE_DECISIONS.md`: UI-ADR-008 gets a step 2 section with the rule, the number of textures capped, a before/after MiB table per screen (Home, Gameplay, Results, Shop/Collection; plus 6-slot Gameplay and tablet noted), the new budgets, and what stayed untouched and why (unobserved, source already <= limit). Report honest numbers even if small.
8. `TASKS.md`: append step 2 evidence to the `SB-M22-026` entry (stays open for VRAM compression, atlasing, lazy card art) and refresh the queue row. Add the new tool `.gd.uid` only if the repo tracks `.uid` for tests (it does not for step 1).

## Acceptance criteria
1. `git diff --name-only main | grep '\.png$'` prints nothing; `git diff --name-only main` contains only: `.import` files under `assets/ui/final/`, `tests/tools/m22_026_texture_measure.gd`, `tools/m22_026_apply_caps.py`, `tests/m22_026_texture_budget.gd`, `docs/07_UI_ASSET_PIPELINE_DECISIONS.md`, `TASKS.md`, optional `coordination/sessions/FACTORY/038-*/` files.
2. `"$GODOT" --headless --path <worktree> -s res://tests/tools/m22_026_texture_measure.gd -- --out=<job>/measure.json` exits 0, 0 SCRIPT ERROR/Parse Error, prints a per-scenario summary and a last line `M22-026 MEASURE: DONE (<n> scenarios, <m> textures)`; the JSON has all 7+ scenarios at both viewports and every texture entry has `max_side_px`. The real save (`AppState.CANONICAL_SAVE_PATH`) is byte-identical before and after (compare hash/mtime), and no `user://*.save` temp remains.
3. `python -I tools/m22_026_apply_caps.py <measure.json>` (dry run) prints every observed texture with measured side, computed limit and decision; every written `process/size_limit` equals `next_pow2(max(2*side,512))`, is >= 512, and is < source max side. No unobserved texture has a changed `.import`. Verify with a grep of `git diff main -- '*.import'`.
4. `"$GODOT" --headless --path <worktree> --import` exits 0 with no error lines after `--write`.
5. `"$GODOT" --headless --path <worktree> -s res://tests/m22_026_texture_budget.gd` prints per-screen MiB lower than step 1 (or equal where nothing was cappable), each within the new budget (measured + ~10%), and last line `M22-026 TEXTURE BUDGET: PASS`. Revert check: setting one new cap to 0 and re-importing makes it print FAIL and exit 1 (record in build log).
6. Suites pass with the CI rule (`python tools/run_suites.py` or direct run, LOCAL_PASS): `m22_025_booster_texture_budget`, `m42_home` (`M42 home evidence: PASS`), `m28_c002_c001_gameplay_v02` (14/14), `m43_c001a_results_foundation` (11/11), `m49_responsive_matrix` (`M49 responsive matrix evidence: PASS (8/8 cases, 0 fail)`), `m50_color_symbols` (10/10), plus any existing screenshot/visual suites that load changed textures (`m28_c002_c002_r01_visual`, `m42_home_v07_safe_area`, `m42_home_composition` if they exist and pass on `main`). Any failure that also fails on `main` is reported as pre-existing.
7. Visual sanity: for the largest-reduction textures, the measure tool's rule guarantees >= 2x the measured size; the build log states the smallest ratio (limit / measured side) among capped textures and it must be >= 2.0.
8. UI-ADR-008 contains the step 2 before/after table per screen with figures equal to the test output; `TASKS.md` step 2 evidence cites the same numbers.
9. `git diff --check main` is clean.

## Out of scope
- Any PNG edit, resizing, re-encode, VRAM/lossy compression (`compress/mode`), mipmap/filter changes, atlasing, lazy loading of card art.
- Changing UI layout, scripts under `scripts/`, or gameplay/economy.
- Adding the new tool or test to the CI workflow suite list.
- Capping textures that were not observed, or any cap below 512.
- Touching the owner's real save, or booting `main.tscn` without `boot_save_path_override`.

## Assumptions
- "Content scale" = physical viewport px / logical viewport px, as in `m49` `_logical`; sizes are recorded in physical pixels because that is what the GPU samples.
- The 2x factor (not step 1's 4x) is owner-requested for this step; it keeps one texel per physical pixel plus 2x headroom for tablet and the press-and-hold magnifiers, so no extra margin is added.
- Catalog card art (collection) is counted only if actually instantiated in the Collection scenario; the budget list stays as is unless measurement shows otherwise.
- Textures in the step-1 5-icon set keep their existing limit when it is already below the new computed one.
- If a scenario cannot be reached headlessly (e.g. 6-slot), the tool records it as skipped with a reason and the build log says so; the cap rule then relies on the other scenarios only for textures seen elsewhere, and unobserved textures stay untouched (conservative).
