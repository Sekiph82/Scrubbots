# M29-C002 evidence — corrected laid-out 59x59 performance (generated in M25-C003)

These files were regenerated by `tests/m29_c002_tempo_retune.gd` after the M25-C003 S0 harness correction. They **supersede only the s8 real-host performance tables** of the V01 evidence one directory up (`../tempo_report.txt`, `../tempo_report.json`). The V01 files are kept unchanged as audit history.

**Why V01 s8 was wrong as production evidence.** The V01 s8 helper built fixture hosts headless, without a sized viewport or a relayout. `SlotOriginProvider` therefore mapped the unlaid slot anchors to board-local `y = 0`: on 59x59, three of six origins were inside the board. Inside-board starts bypass the M52 prefilter and use the interior debug planner, which produced the reported 0.9–3.4 s lanes. See `coordination/sessions/M25-C002/M25_59X59_TARGET_SELECTION_FINDINGS_V01.md`.

**What changed in s8.**
- Every host is a 1080x2160 `SubViewport` production host: settle, build, relayout, settle; after +1 Slot it settles and relayouts again; then `reset_runtime()`.
- Every slot origin is asserted finite and **below the board** before measurement. The origins are listed per run in `tempo_report.json` (`slot_origins`).

**What did not change.** The M29 tempo constants and behaviour (9/18 cells/s, 1/3 and 1/6 s cadence, one lane per frame) and sections s1–s7 of the suite. These were re-run and still pass.

**Code state.** This evidence also includes the M25-C003 S1 prefilter. Before/after timing on the full level is in `coordination/sessions/M25-C003/evidence/`.
