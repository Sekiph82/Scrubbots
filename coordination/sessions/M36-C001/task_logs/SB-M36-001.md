# SB-M36-001 — Legacy migration

Status: IMPLEMENTED
Requirement: the old runtime rule mapping EASY=20..29 / MEDIUM=30..39 /
HARD=40..49 / VERY_HARD=50..59 must no longer define player-facing difficulty.
Production board envelope stays 20..59 per dimension, rectangular allowed.
Legacy M21 compatibility may remain only via a clearly isolated seam.

## Approach
Player-facing class now comes from the owner-locked cadence config, read by
`scripts/difficulty/difficulty_progression_v1.gd` (level number -> class), not
from board dimensions. The legacy dimension-band `DifficultyRules` /
`ProductionLevelValidator` is retained ONLY as the structural M21 compatibility
gate inside the M35 catalog, and it no longer decides class. The isolated
Difficulty V1 compatibility seam is `difficulty_v1_catalog_check.gd`, which
validates class token + envelope but explicitly does not derive class from
dimensions.

## Direct tests
`tests/m36_difficulty_v1.gd`:
- `_cadence_pattern` — class comes from cadence, repeats every 10 levels;
- `_board_size_cannot_determine_class` — dimensions do not rewrite class;
- `_catalog_compatibility` — M35 catalog validates against envelope 20..59.

## Failure condition
Class derived from dimensions, or envelope narrowed below 20..59.

## Actual
PASS.

## Note
`DifficultyRules` BANDS are intentionally left in place per CLAUDE.md §6
("Legacy runtime validators may retain old bands temporarily during audited
migration"). Full removal is a later migration step; M36 removes their
authority over player-facing class.
