# SB-M36-003 — Challenge components (W/C/A/U/B/R/S)

Status: IMPLEMENTED
Requirement: implement/version Challenge V1 components exactly from the locked
config/docs. All submetrics finite and clamped 0..1. Final Challenge finite and
clamped 0..100. No silent coefficient change under version 1.

## Production owner
`scripts/difficulty/challenge_score_model_v1.gd`:
- reads `data/config/difficulty_score_model_v1.json` (schema
  `scrubbots-difficulty-score-model/v1`, version stamped via `model_version()`);
- `challenge_score(vec)` implements
  `D = 100*(0.10W+0.15C+0.20A+0.20U+0.15B+0.10R+0.10S)`;
- every submetric clamped to [0,1] (`_clamp01` also maps NaN/Inf -> 0);
- `session_load` and `frustration_risk` implemented from their own weight sets;
- coefficients read from config, never hardcoded — no silent change possible
  without a config edit (which is a versioned, visible diff).
- `workload_submetric(cell_count)` (sqrt transform, reference bounds) and
  `color_submetric(distinct, entropy)` provide the two structurally-derivable
  submetrics; A/U/B/R/S are supplied by canonical solver/routing analysis.

## Direct tests
`tests/m36_difficulty_v1.gd::_challenge_score_bounds`:
- empty vector -> 0;
- all-ones vector -> 100 (weights sum to 1.0);
- extreme (5.0/-3.0/NaN/Inf) inputs clamp to a finite [0,100] result.

## Failure condition
Any non-finite or out-of-[0,100] Challenge Score, or a coefficient not matching
the locked config.
